"Role:
    It acts as a middleman between services so they don't communicate directly."

"Queue

A queue stores messages until they are processed.

Role: Holds messages temporarily.

Producer

The service that sends messages to RabbitMQ.

Role: Creates and sends messages.

Consumer

The service that receives messages from RabbitMQ.

Role: Reads and processes messages.

Message

The data being transferred between services.

Role: Carries information such as OTPs, order details, or email requests."

📦 How the Flow Works:
✅ 1. User hits login API (/login)
A 6-digit OTP is generated.
The OTP is stored in Redis.
Then, we send a message to RabbitMQ (to the send-otp queue), which contains:
{
  "to": "user@example.com",
  "subject": "Your OTP Code",
  "body": "Your OTP is 123456. It is valid for 5 minutes."
}
📤 2. Producer — Publishing to RabbitMQ
Inside the LoginUser controller, we use a function like:
publishToQueue("send-otp", message)

to push the OTP email job to RabbitMQ.

📥 3. Consumer — Worker picks the job
In a separate file (usually consumer.ts), we run a background worker which:
Listens to the send-otp queue.
When a message arrives, it reads the email details and uses nodemailer (or any mail service) to send the email.
After success, it acknowledges the message:
channel.ack(msg)

Why Use RabbitMQ?

✅ Non-blocking: The user doesn't have to wait for the email to be sent — the API responds instantly.

✅ Scalable: We can send thousands of emails by running multiple consumers (workers).

✅ Reliable: If email fails, we can requeue the message and try again.

============================================================
             USER SERVICE — API REFERENCE
         Base URL: http://localhost:5000/api/v1
============================================================

------------------------------------------------------------
  PUBLIC ROUTES (No token required)
------------------------------------------------------------

  [POST]  /login
  → Request OTP to be sent to email
  → Body: { "email": "you@example.com" }
  → Rate limited: max 3 requests per 5 minutes

  [POST]  /verify
  → Verify OTP and receive JWT token
  → Body: { "email": "you@example.com", "otp": "123456" }
  → Response: { message, user, token }

------------------------------------------------------------
  PROTECTED ROUTES (Authorization: Bearer <token>)
------------------------------------------------------------

  [GET]   /me
  → Get the currently logged-in user's profile

  [PUT]   /update/user
  → Update the currently logged-in user's name
  → Body: { "name": "New Name" }
  → Response: { message: "User Updated", user, token }

  [GET]   /user/all
  → Get all registered users

  [GET]   /:id
  → Get a single user by their MongoDB ID
  → Params: id = MongoDB ObjectId of the user

------------------------------------------------------------
  POSTMAN TIP
------------------------------------------------------------
  1. Create a Collection Variable named "token"
  2. After /verify, save the token from the response
  3. In all protected requests, set:
     Authorization → Bearer {{token}}
============================================================

============================================================
              MULTER + CLOUDINARY — IMAGE UPLOAD
============================================================

HOW IT WORKS (flow):
  User sends image → Multer → Cloudinary → Save URL in MongoDB

------------------------------------------------------------
  MULTER
------------------------------------------------------------
  Express cannot read files from requests by default.
  Multer parses multipart/form-data and puts the file on req.file.
  That's its only job — read the file from the request.

------------------------------------------------------------
  CLOUDINARY
------------------------------------------------------------
  Cloud storage service for images/videos.
  You never store images in MongoDB (it's a DB, not a file server).
  Upload to Cloudinary → get back a URL → save that URL in MongoDB.
  e.g. https://res.cloudinary.com/your-cloud/image/upload/abc123.jpg

------------------------------------------------------------
  MULTER-STORAGE-CLOUDINARY
------------------------------------------------------------
  Connects Multer and Cloudinary together.
  Instead of saving to disk, Multer streams the file directly to Cloudinary.
  By the time it hits your controller:
    - Image is already uploaded to Cloudinary
    - req.file contains the Cloudinary URL
